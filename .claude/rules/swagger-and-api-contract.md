# Swagger and API contract

- `docs/` (`docs.go`, `swagger.json`, `swagger.yaml`) is generated by `swag init -g main.go`
  Never edit it by hand.
- Every handler has a swag comment block directly above it: `@Summary`, `@Description`, `@Tags`
  (zone name, lowercase), `@Accept`/`@Produce json`, `@Param` for each path/query/body input,
  `@Success` with the response struct, and `@Router /path [method]`. Router paths are relative to
  `@BasePath /api` (declared in `main.go`) and use the same param names as the Gin route
  (`/transaction/{transactionID}`).
- Add `@Failure` annotations for the error responses the endpoint can actually return, with
  `response.ErrorResponse` (and `response.ValidationErrorResponse` for 422), so clients get typed
  errors.
- API clients are generated from this Swagger doc, so treat any change to a request/
  response struct, JSON tag, route, or status code as a **breaking-change candidate**: keep
  changes additive when possible.
- JSON field names are camelCase. Money fields in response/request DTOs are `float64` or
  `decimal.Decimal` as already used by the surrounding DTOs — match the neighbouring endpoints
  rather than introducing a new representation (see `money-and-domain.md`).
- Optional query params are pointers or have explicit defaults, and are documented with
  `@Param name query type false "..."`. UUID params use `Format(uuid)` in the annotation.
- After changing annotations or DTOs, run `make swagger` and include the regenerated
  `docs/` in the same change.
